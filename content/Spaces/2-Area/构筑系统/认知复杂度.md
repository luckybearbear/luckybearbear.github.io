# 认知复杂度 (Cognitive Complexity)

> 代码不仅要让机器执行,更要让人理解

## 核心思想

**认知复杂度**(Cognitive Complexity)是衡量代码**可读性**的指标,它评估读者在理解代码时需要付出的脑力努力。与传统的**圈复杂度**(Cyclomatic Complexity)不同,认知复杂度更关注**人类阅读代码的认知负担**,而不是代码的控制流数量。

> "Code is read much more often than it is written." — Guido van Rossum

---

## 一、为什么需要认知复杂度?

### 1.1 圈复杂度的局限

**圈复杂度(Cyclomatic Complexity)**:
- 定义: 代码中独立路径的数量
- 计算: 判断语句(if、while、for等)的数量 + 1
- 问题: **不能反映代码的可读性**

**问题示例:**

```java
// 圈复杂度: 5 (4个if + 1)
// 认知复杂度: 2 (嵌套层级浅,容易理解)
if (condition1) {
    doSomething();
}
if (condition2) {
    doSomething();
}
if (condition3) {
    doSomething();
}
if (condition4) {
    doSomething();
}
```

```java
// 圈复杂度: 5 (4个if + 1)
// 认知复杂度: 10 (嵌套深,难以理解)
if (condition1) {
    if (condition2) {
        if (condition3) {
            if (condition4) {
                doSomething();
            }
        }
    }
}
```

**两者的圈复杂度相同,但可读性天差地别!**

### 1.2 认知复杂度的目标

**核心理念:**
- 从**人类读者**的角度评估代码
- 关注**嵌套、跳转、中断**等增加认知负担的因素
- 鼓励编写**易于理解**的代码

**提出者**: SonarSource (2016年)
**论文**: *Cognitive Complexity: A new way to measure understandability of code*

## 二、认知复杂度的计算规则

### 2.1 基本增量规则

**增加认知复杂度的操作:**

| 操作类型 | 增量 | 说明 |
|---------|------|------|
| **if、三元运算符** | +1 | 条件判断 |
| **else、else if** | +1 | 额外的分支 |
| **switch、case** | +1 | 多分支选择 |
| **for、while** | +1 | 循环 |
| **catch** | +1 | 异常处理 |
| **break、continue、goto** | +1 | 控制流跳转 |
| **递归调用** | +1 | 递归增加理解难度 |

### 2.2 嵌套惩罚规则

**嵌套层级**: 每进入一层嵌套,**额外增加**当前嵌套层级数的复杂度

**示例:**

```java
// 认知复杂度: 0
void simple() {
    doSomething();
}
```

```java
// 认知复杂度: 1 (if + 0层嵌套)
void oneIf() {
    if (condition) {  // +1
        doSomething();
    }
}
```

```java
// 认知复杂度: 3 (if + 1 + if + 1)
void nestedIf() {
    if (condition1) {           // +1 (基础增量)
        if (condition2) {       // +1 (基础增量) + 1 (1层嵌套)
            doSomething();
        }
    }
}
```

```java
// 认知复杂度: 7
void deeplyNested() {
    if (c1) {                    // +1
        if (c2) {                // +1 + 1(嵌套)
            if (c3) {            // +1 + 2(嵌套)
                if (c4) {        // +1 + 3(嵌套)
                    doSomething();
                }
            }
        }
    }
}
// 计算: 1 + 2 + 3 + 4 = 10 ❌ 错误!
// 正确: if增量都是+1,嵌套是额外增量
// c1: +1
// c2: +1 + 1(嵌套)
// c3: +1 + 2(嵌套)
// c4: +1 + 3(嵌套)
// 总计: 4 + 6 = 10
```

### 2.3 实际计算示例

**示例1: 简单循环**

```java
// 认知复杂度: 1
void printNumbers(int n) {
    for (int i = 0; i < n; i++) {  // +1
        System.out.println(i);
    }
}
```

**示例2: 嵌套条件**

```java
// 认知复杂度: 4
void check(int a, int b) {
    if (a > 0) {              // +1
        if (b > 0) {          // +1 + 1(嵌套) = 2
            System.out.println("both positive");
        } else {              // +1
            System.out.println("a positive");
        }
    } else {                  // +1
        System.out.println("a not positive");
    }
}
// 总计: 1 + 2 + 1 + 1 = 5 ❌
// 正确计算:
// if (a > 0): +1
//   if (b > 0): +1 + 1(嵌套)
//   else: +1
// else: +1
// 总计: 1 + 2 + 1 + 1 = 5
```

**示例3: 混合结构**

```java
// 认知复杂度: 6
void process(int[] numbers) {
    for (int num : numbers) {         // +1
        if (num > 0) {                 // +1
            if (num % 2 == 0) {        // +1 + 1(嵌套)
                System.out.println("positive even");
            } else {                  // +1
                System.out.println("positive odd");
            }
        } else if (num < 0) {         // +1
            System.out.println("negative");
        } else {                      // +1
            System.out.println("zero");
        }
    }
}
// 计算: 1(for) + 1(if) + 2(嵌套if) + 1(else) + 1(else if) + 1(else) = 7
```

## 三、认知复杂度 vs 圈复杂度

### 3.1 核心区别

| 维度 | 圈复杂度 | 认知复杂度 |
|------|----------|------------|
| **关注点** | 控制流数量 | 人类认知负担 |
| **计算基础** | 独立路径数 | 嵌套 + 跳转 |
| **目标** | 测试覆盖率 | 代码可读性 |
| **提出时间** | 1976年 | 2016年 |
| **适用场景** | 测试用例设计 | 代码审查、重构 |

### 3.2 对比示例

**示例1: 扁平结构 vs 深层嵌套**

```java
// 圈复杂度: 5, 认知复杂度: 5
public void flat() {
    if (a) doA();
    if (b) doB();
    if (c) doC();
    if (d) doD();
}
```

```java
// 圈复杂度: 5, 认知复杂度: 10
public void nested() {
    if (a) {
        if (b) {
            if (c) {
                if (d) {
                    doD();
                }
            }
        }
    }
}
```

**结论**: 圈复杂度相同,但认知复杂度差异巨大!

### 3.3 使用建议

- **圈复杂度**: 用于评估测试需求
  - 确定需要的测试用例数量
  - 设置上限(如15)
- **认知复杂度**: 用于评估代码质量
  - 指导重构方向
  - 设置更严格的上限(如15)

## 四、降低认知复杂度的策略

### 4.1 提前返回 (Early Return)

**反模式: 深层嵌套**

```java
// 认知复杂度: 10
public void process(User user) {
    if (user != null) {
        if (user.isActive()) {
            if (user.hasPermission()) {
                if (user.isValid()) {
                    doProcess(user);
                }
            }
        }
    }
}
```

**改进: 提前返回**

```java
// 认知复杂度: 4
public void process(User user) {
    if (user == null) return;           // +1
    if (!user.isActive()) return;       // +1
    if (!user.hasPermission()) return;  // +1
    if (!user.isValid()) return;        // +1

    doProcess(user);
}
```

**优势:**
- 减少嵌套层级
- 每个条件独立清晰
- 主流程在最后,一目了然

### 4.2 提取方法 (Extract Method)

**反模式: 长方法**

```java
// 认知复杂度: 15+
public void processOrder(Order order) {
    if (order != null) {
        if (order.getItems() != null) {
            for (OrderItem item : order.getItems()) {
                if (item.getProduct() != null) {
                    if (item.getProduct().isAvailable()) {
                        if (item.getQuantity() > 0) {
                            // 处理订单项...
                            // 50行代码
                        }
                    }
                }
            }
        }
    }
}
```

**改进: 提取方法**

```java
// 认知复杂度: 3
public void processOrder(Order order) {
    if (order == null) return;

    List<OrderItem> items = order.getItems();
    if (items == null) return;

    processItems(items);
}

// 认知复杂度: 6
private void processItems(List<OrderItem> items) {
    for (OrderItem item : items) {
        if (isValidItem(item)) {
            processItem(item);
        }
    }
}

// 认知复杂度: 3
private boolean isValidItem(OrderItem item) {
    return item.getProduct() != null
        && item.getProduct().isAvailable()
        && item.getQuantity() > 0;
}
```

**优势:**
- 每个方法职责单一
- 复杂度分散
- 方法名自文档化

### 4.3 卫语句 (Guard Clauses)

**反模式: 复杂条件**

```java
// 认知复杂度: 8
public void calculate(int a, int b, int c) {
    if (a > 0 && b > 0 && c > 0) {
        if (a < 100 && b < 100 && c < 100) {
            if (a + b > c && a + c > b && b + c > a) {
                // 三角形计算
            }
        }
    }
}
```

**改进: 卫语句**

```java
// 认知复杂度: 4
public void calculate(int a, int b, int c) {
    if (!isValidTriangle(a, b, c)) return;  // 封装验证逻辑

    // 三角形计算
}

private boolean isValidTriangle(int a, int b, int c) {
    return a > 0 && b > 0 && c > 0
        && a < 100 && b < 100 && c < 100
        && a + b > c && a + c > b && b + c > a;
}
```

### 4.4 策略模式 (Strategy Pattern)

**反模式: 大量if-else**

```java
// 认知复杂度: 10+
public void processPayment(Payment payment) {
    if (payment.getType() == PaymentType.ALIPAY) {
        // 支付宝处理逻辑
    } else if (payment.getType() == PaymentType.WECHAT) {
        // 微信处理逻辑
    } else if (payment.getType() == PaymentType.CARD) {
        // 银行卡处理逻辑
    } else if (payment.getType() == PaymentType.PAYPAL) {
        // PayPal处理逻辑
    }
    // ...更多支付方式
}
```

**改进: 策略模式**

```java
// 认知复杂度: 1
public void processPayment(Payment payment) {
    PaymentProcessor processor = processorFactory.get(payment.getType());
    processor.process(payment);
}

// 策略接口
interface PaymentProcessor {
    void process(Payment payment);
}

// 具体策略
class AlipayProcessor implements PaymentProcessor {
    public void process(Payment payment) {
        // 支付宝处理逻辑
    }
}
```

### 4.5 多态 (Polymorphism)

**反模式: 类型判断**

```java
// 认知复杂度: 7
public void draw(Shape shape) {
    if (shape instanceof Circle) {
        drawCircle((Circle) shape);
    } else if (shape instanceof Rectangle) {
        drawRectangle((Rectangle) shape);
    } else if (shape instanceof Triangle) {
        drawTriangle((Triangle) shape);
    }
}
```

**改进: 多态**

```java
// 认知复杂度: 0 (调用方)
public void draw(Shape shape) {
    shape.draw();  // 多态调用
}

abstract class Shape {
    abstract void draw();
}

class Circle extends Shape {
    void draw() {
        // 绘制圆形
    }
}
```

### 4.6 使用Optional避免null检查

**反模式: 链式null检查**

```java
// 认知复杂度: 6
public String getUserEmail(User user) {
    if (user != null) {
        Profile profile = user.getProfile();
        if (profile != null) {
            Contact contact = profile.getContact();
            if (contact != null) {
                return contact.getEmail();
            }
        }
    }
    return "";
}
```

**改进: Optional**

```java
// 认知复杂度: 1
public String getUserEmail(User user) {
    return Optional.ofNullable(user)
        .map(User::getProfile)
        .map(Profile::getContact)
        .map(Contact::getEmail)
        .orElse("");
}
```

## 五、认知复杂度工具与标准

### 5.1 代码质量标准

**SonarQube默认阈值:**

| 复杂度级别 | 方法 | 类 |
|------------|------|-----|
| **好** | ≤ 15 | ≤ 100 |
| **需改进** | 16-30 | 101-200 |
| **不可接受** | > 30 | > 200 |

**Google Java Style:**
- 方法认知复杂度: 建议不超过10
- 禁止超过15

**最佳实践:**
- **简单方法**: 0-5
- **中等方法**: 6-10
- **复杂方法**: 11-15 (应考虑拆分)
- **警示**: > 15 (必须重构)

## 六、认知复杂度的局限

### 6.1 无法衡量的问题

**1. 业务复杂度**

```java
// 认知复杂度低,但业务逻辑复杂
public double calculateInterest(Loan loan) {
    // 复杂的利息计算公式
    // 涉及复利、罚息、优惠等
    // 即使代码简单,理解业务规则也需要时间
}
```

**2. 命名质量**

```java
// 认知复杂度相同,可读性不同
if (a > b && c < d) { }  // 命名差
if (principal > minAmount && rate < maxRate) { }  // 命名好
```

**3. 上下文依赖**

```java
// 需要理解整个系统才能理解
context.getFactory().getProcessor().getHandler().handle();
```

**4. 数据复杂度**

```java
// 复杂的数据结构即使处理简单也难理解
void process(Map<String, List<Map<Integer, Object[]>>> data) {
}
```

### 6.2 结合其他指标

**综合代码质量评估:**
- **认知复杂度**: 可读性
- **圈复杂度**: 测试需求
- **代码行数**: 规模
- **代码重复率**: DRY原则
- **测试覆盖率**: 质量保证
- **技术债务**: 维护性

## 七、最佳实践

### 7.1 编写低复杂度代码的原则

**1. 单一职责原则 (SRP)**
- 每个方法只做一件事
- 降低认知负担

**2. 保持简短**
- 方法不超过20行
- 每个方法不超过3个参数

**3. 描述性命名**
- 变量名、方法名自解释
- 减少理解成本

**4. 避免深层嵌套**
- 嵌套不超过3层
- 使用提前返回

**5. 优先使用语言特性**
- 使用Optional而非null检查
- 使用Stream而非循环
- 使用多态而非类型判断

### 7.2 代码审查重点关注

**高认知复杂度的信号:**
- ❌ 多层嵌套的if-else
- ❌ 长方法(>50行)
- ❌ 多个条件组合
- ❌ 复杂的循环逻辑
- ❌ 大量的break/continue

**低认知复杂度的特征:**
- ✅ 扁平的结构
- ✅ 短小的方法
- ✅ 清晰的命名
- ✅ 单一职责
- ✅ 提前返回

### 7.3 团队实践

**1. 设置CI/CD检查**


**2. 代码审查模板**

**3. 重构驱动开发**
- 先写简单代码
- 测试通过后重构
- 持续降低复杂度

**4. 知识分享**
- 定期分享重构技巧
- 代码审查会议
- 复杂度案例分析
